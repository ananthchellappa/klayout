Read these first

Three ideas that make the codebase make sense

gsi · gsiDecl*.cc

Declare once, script in two languages

Every scriptable class has a gsiDecl*.cc file next to it. rba and pya turn those declarations into Ruby and Python classes at runtime, and the @brief strings become the API reference. gsiqt does the same for Qt, which is why pya.QTcpServer exists inside KLayout.

gsi::Class<db::Box> decl_Box ("db", "Box",
  gsi::method ("width", &db::Box::width,
    "@brief Gets the width of the box\n") + …);

To find out what a script can do, grep gsi::method ("name".

db

A hierarchical layout database

Layout owns Cells. Each cell holds per-layer Shapes plus Instances, all in integer database units. Region/Edges have flat and deep implementations, and deep mode makes DRC and LVS hierarchical. LayoutToNetlist extracts a Netlist. LayoutVsSchematic compares it to a reference and produces a NetlistCrossReference.

laybasic → lay

Everything interactive is a plugin

lay::Plugin/PluginDeclaration power the edit services, rulers, browsers and net tracer. They register statically, add menu entries and mouse modes, and receive configuration through the Dispatcher. Scripts get the same hooks via lay.PluginFactory. Rendering runs on worker threads. Scripts and UI run on the Qt main thread.

layApplication.cc · init_app → run

What happens at startup

  1. Gather search paths: ~/.klayout, $KLAYOUT_PATH, and salt packages under ~/.klayout/salt.
  2. Register each path's macros/ (Ruby) and pymacros/ (Python) folders.
  3. Run autorun-early macros, then build the main window and load technologies.
  4. Run autorun macros, then any -r / -rm scripts from the command line.
  5. Enter the Qt event loop. All script code runs on this single thread.

Useful options: -e edit mode · -z no GUI · -rr f run a script and stay open · -rd k=v script variable · -rx skip autorun · -j dir extra macro folder.

Goal · an open "Layout XL"

Cross-probing Xschem and KLayout

I found no existing open-source tool that does this. Both tools already have the pieces, so a first version needs no C++ changes in either: a KLayout autorun macro and about 100 lines of Xschem Tcl.

Xschem Tcl

  • TCP server, off by default (--tcp_port). Evaluates Tcl, one request per connection
  • select_inst {x1.x2.m4}, probe_net {x1.x2.net5}, zoom_selected
  • Reads selection via selected_set, selected_wire, get sch_path
  • No selection event. Hook by wrapping the infowindow proc
  • LVS netlist export (lvs_netlist=1) with PDK params
probe · JSON lineselection in Xschem
select_inst / probe_netTcl over loopback
layout_export · JSONinstances, params, pin→net

KLayout Python autorun

  • No built-in server. Use pya.QTcpServer (needs a Qt-bindings build)
  • Name map: LayoutVsSchematic.xref → other_net_for
  • Highlight: netlist_browser.current_path = … or lay.Marker
  • Events: on_selection_changed, browser on_probe
  • Place PCells: create_cell(pcell, lib, params) + set_property

Phased plan

From a probe loop to schematic-driven layout

P0LVS-BACKED

Cross-probe an existing layout

  • Xschem writes the LVS netlist. KLayout's PDK LVS deck produces a .lvsdb, which is loaded into the netlist browser.
  • Xschem → KLayout: xref.other_net_for, then current_path= highlights and zooms.
  • KLayout → Xschem: browser on_selection_changed, then probe_net {…} over Tcl.
Done when: clicking a net in either tool highlights it in the other on the sky130 inverter.
P1NO LVS

Instance cross-probe through properties

  • Stamp each placed instance with its schematic path (set_property, string keys in OASIS).
  • On layout selection, read the property and send select_inst. In the other direction, find the instance by property, then select_object + zoom_fit_sel.
P2GENERATE

Schematic-driven layout

  • Xschem layout_export produces JSON: path, symbol, evaluated W/L/nf/m, pin→net.
  • KLayout places PDK PCells through a per-PDK parameter map and draws flylines as markers between pins on the same net.
  • ECO update: diff the export against the stamped instances, then add, delete or re-parameterize while keeping placement.
P3NATIVE

Polish, and C++ if needed

  • Net/instance dock panel, unrouted-net report, incremental LVS.
  • Move hot paths into a lay::Plugin under src/plugins/tools/ if the Python markers are too slow.

Risks

Python never releases the GILBackground threads starve and asyncio blocks the GUI. Drive everything from Qt signals or a QTimer.
No Qt bindings, no serverBuilds with -without-qtbinding and the pip module lack QTcpServer. Fall back to a small C++ plugin.
Browser highlights are transientThey disappear when the netlist browser closes. Draw our own markers from shapes_of_net, mapped from the internal layout.
Xschem's server runs any TclIt binds all interfaces with no auth. Keep both directions on 127.0.0.1, which matters on AWS/Docker.
Device names driftThe SPICE prefix (XM3 vs M3) and the reader's naming can differ. Verify on the first real design.
